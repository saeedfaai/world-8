# Diagnostic Memory — SSRN v0.2 Floating-Point Receipt Determinism

Date: 2026-08-27
Status: FIX IN VALIDATION
Scope: `experiments/ssrn_market_replay_v0_2`

## Symptom

After PR #13 was opened, a later workflow-generated evidence commit moved the branch head. The merge correctly failed because the requested expected head SHA was stale. Inspection of the generated commit showed that only `results/summary.json` changed, with several ensemble configuration weights differing at approximately the 1e-14 decimal level between otherwise equivalent reruns.

Rejected merge attempt safety behavior:
- GitHub returned HTTP 409 because the head branch had moved.
- No merge occurred.
- Canonical `main` was not modified.

## Root cause class

The scientific point estimates and CSV outputs were unchanged at report precision, but `summary.json` serialized raw binary floating-point results at full Python precision. Harmless low-order numerical jitter from the numerical stack therefore produced a different byte representation and a different Git commit.

This is a reproducibility defect in the **receipt representation**, even when the scientific result is materially identical.

## Fix

1. Machine-readable summary floats are canonicalized to 12 decimal places before JSON serialization.
2. Schema advanced from `WORLD8_SSRN_MARKET_ABLATION_RESULT/2.0` to `/2.1` and records `canonical_float_decimals: 12`.
3. Workflow now runs the complete ablation generator twice in the same pinned environment and compares SHA256 hashes for:
   - `results/metrics.csv`
   - `results/bootstrap_robustness.csv`
   - `results/summary.json`
4. Merge is blocked until the bitwise determinism gate passes.

## Engineering lesson

Scientific reproducibility has at least two distinct requirements:
- **numerical/evidentiary reproducibility**: conclusions and metrics remain within declared precision/tolerance;
- **artifact reproducibility**: the same governed run produces byte-identical receipts where byte identity is claimed.

Raw floating-point serialization MUST NOT be treated as a canonical artifact representation. Canonical precision/quantization must be explicit in the schema.

## General rule

For generated evidence intended for hashes, Git lineage, DOI snapshots, or proof receipts:
- canonicalize floating-point precision explicitly;
- sort keys / stable field order;
- stable newline/encoding;
- deterministic compression when applicable;
- add a repeated-run SHA256 gate when practical.
